# Architecture and team contracts

Toolbar icon click on the Canvas tab → planner opens as a full tab (`popup.html`, reused if open) bound to that tab through activeTab → Sync button → paginated courses API, then per course three parallel assignment requests for open work only (`bucket=future|overdue|undated`; rubrics included) → normalized assignment → extension service worker → loopback API → mock or Snowflake Cortex → validated estimate → local browser cache → popup planner.

The extension uses activeTab and scripting to work with custom Canvas domains without permanent access to every website. Canvas credentials stay in the signed-in tab. The collector requires HTTPS, except plain `http` on `localhost`/`127.0.0.1` for the mock Canvas (`npm run mock-canvas`), which serves the same endpoints for end-to-end demos and tests. Linked-file reading is off by default (`READ_FILES` in `extension/popup.js`); file handling is planned for the AI step, and sync sends `attachments: []`. When enabled, attachments are files linked from an assignment description (same Canvas origin only): plain-text files only (CSV, TSV, JSON, XML, YAML, TXT, MD, HTML, notebooks, and code/config files) up to 100 KB. Documents (PDF, DOCX, PPTX, XLSX, DOC, PPT, RTF, ODT up to 25 MB) are not read; they are downloaded in the tab, passed to the service worker as base64, and stored in the extension's IndexedDB (`extension/files-db.js`, database `assignment-files`, keyed by Canvas host and file ID, stored once and linked to every assignment that references it). Re-syncs skip files whose Canvas `updated_at` is unchanged. During sync the popup shows a live line per course (current assignment, file, and download progress); sync fails only after 2 minutes without progress, with a 30-minute cap. Stored documents never go to the server or Snowflake; they persist until Clear data or extension removal, and the popup offers a download link per file. Images, archives, binaries and secrets files are skipped. Files hosted on another origin without CORS are skipped as 'download blocked'. Sync is a read operation and is explicit. An API-based collector is more stable than DOM selectors; rendered-page scraping can be a separate adapter if institution settings block API access.

POST /api/estimate takes `{assignments: Assignment[]}` and returns `{assignments: PlannedAssignment[]}`. Assignment fields: unique string id, title, course, plain-text description (12,000 characters max), ISO dueAt or null, nonnegative points, string[] submissionTypes, and optional attachments `{name, text}[]` (at most 5 files, 4,000 characters each, 8,000 per assignment). Maximum batch is 100 and the request body is capped at 4 MB. Extra fields, including URLs, are discarded at the server boundary. Estimate fields: integer estimatedMinutes (5–10,080), reason, provider; planner adds ISO startAt or null. GET / (alias /assignments) returns the latest batch received, in memory only, as pretty-printed `{syncedAt, catchUp, upcoming}` where each item is `{course, title, description, dueDate, attachments}`; Catch Up is past-due, Upcoming is everything else including undated. In local mode it answers only to localhost/127.0.0.1 Host headers; hosted mode requires bearer authentication. Errors use `{error: string}` with HTTP 400/413/415 for invalid requests or 502 for inference failure.

Snowflake uses Cortex's OpenAI-compatible chat completions endpoint with a server-held Programmatic Access Token (PAT). Provider selection defaults to auto: no credentials uses mock; either credential supplied selects Snowflake, and incomplete credentials fail. The default model is llama3.1-8b, optionally overridden by SNOWFLAKE_MODEL. Account privileges and model availability must allow the selected model. Model output must be a JSON object or one complete Markdown JSON fence; malformed/schema-invalid output fails the request rather than silently substituting mock estimates. Generation uses temperature 0 and a 512-token output cap per assignment in the group (up to 5,120). `INFERENCE_BATCH_SIZE` selects 1, 5 (demo default) or 10; a conservative 16,000-byte serialized input budget splits long groups, while an oversized singleton is still subject to provider limits. Multi-item prompts request JSON arrays keyed by local numeric IDs. Response order is ignored; duplicate/unknown IDs invalidate the group. Valid partial results are retained, and missing/invalid estimates receive one singleton retry. Malformed/truncated or ambiguously mapped groups receive one singleton attempt per item. There are no transport retries or recursive fallbacks. No persistence in Snowflake is implemented: assignment content is sent for inference only.

The server binds to loopback by default. A non-loopback `HOST` enables private hosted mode: startup requires `API_ACCESS_KEY` (32+ characters) and explicit extension origins. All data routes require bearer authentication; `/health` and OPTIONS remain public. This is one user identity, not a multi-user service. Hosted mode permits authenticated job polling on the deployed hostname, limits authenticated requests and estimate starts, disables diagnostic files, and expires payloads/jobs 15 minutes after creation. Use one instance. The extension loads URL/key settings from chrome.storage.local on each call and requests optional permission only for the selected HTTPS origin. See [deployment and retention](deployment.md). Default CORS allows extension origins for local development; ALLOWED_ORIGINS can pin one extension ID. CORS is not authentication. Use hosted mode behind HTTPS when exposing the server beyond loopback. No assignment payloads or credentials are logged. In local mode, each sync posts a sanitized bottleneck report to `POST /api/sync-report`, saved in `sync-logs/` (gitignored, or `SYNC_LOG_DIR`). Inference also writes incremental JSONL traces with a batch ID, assignment indices, input/output sizes, Snowflake request ID, token usage, finish reason, per-stage timing and typed errors. New reports omit names, descriptions, credentials and raw model content. Browser data persists until Clear data or extension removal.

Inference now uses `POST /api/estimate-jobs` and one-second `GET /api/estimate-jobs/<id>` polling, with three workers processing groups and stable output order. `DELETE` cancels. Each request is bounded at 45 seconds, jobs at 10 minutes, and unpolled jobs are cancelled after about 60–70 seconds. Failures cancel active requests and retain partial diagnostics. Jobs are in memory and expire 15 minutes after the last poll locally, or 15 minutes after creation in hosted mode; one batch runs at a time. The compatibility `/api/estimate` endpoint still responds synchronously. See [diagnostics](diagnostics.md).

Known limits: Popup closure can interrupt the UI flow. No availability calendar, conflict resolution, attachments, personalized pace, actual-time feedback, institution-wide Canvas validation, or multi-user production deployment is included.

References: [Chrome service workers](https://developer.chrome.com/docs/extensions/develop/migrate/to-service-workers), [Canvas assignments API](https://developerdocs.instructure.com/services/canvas/resources/assignments), [Snowflake Cortex REST API](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-rest-api).

Batch comparison details: [batching](batching.md). Group diagnostics count each provider call and its tokens once; per-assignment durations in grouped mode reflect time spent in the whole group, including fallback. Mock estimates bypass Snowflake and retain the same keyword heuristic in every mode.
